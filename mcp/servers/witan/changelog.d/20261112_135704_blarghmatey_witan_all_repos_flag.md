### Changed

- BREAKING: `repo=""` no longer means "every repo". The most common malformed witan tool call in agent transcripts is an empty value for `repo` (`"repo": }`), which the client rejects before it is sent, and the documented empty-string sentinel is the suspected cause. Every tool that could span repos now takes `all_repos=True` for that: `memory_search`, `memory_list`, `memory_contradictions`, `recall`, `task_list`, `task_search`, `task_ready`, `workflow_project_list`, `workflow_project_search` and `workflow_trace_list`. On `memory_store`, `task_create` and `workflow_session_start`, `all_repos=True` files the row under no repo (what `repo=""` did there). An empty `repo` is refused with an error naming `all_repos`, as is `repo` together with `all_repos`. `task_claim` and `task_for_branch` refuse an empty `repo` but take no `all_repos`, because they use `repo` only to key a branch.
- The `witan` CLI's `--all-repos` sends `all_repos=True`, and the web UI sends `all_repos: true` where its repo filter is "All repos".
- An un-upgraded remote-proxy client is refused on any call that sends `repo=""`, including `witan` CLI `--all-repos` before this release. Its `all_repos=True` calls are refused too, because an older witan-core proxy injects the detected repo beside the flag. Upgrade witan-council and witan-core together.
