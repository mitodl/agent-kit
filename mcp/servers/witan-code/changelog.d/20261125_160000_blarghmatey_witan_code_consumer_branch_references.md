### Added

- `code_find_references` takes an optional `consumer_branches` (`{repo URI: git branch}`). Each repo named there whose branch has a bridge overlay has its uses of the definition read from that overlay instead of from the view the definition's repo is read at, before the 200-row cap. The language server passes the branch of every workspace folder on a non-default branch, so Find References on a library definition lands on the line a consumer's feature branch has, rather than the default branch's line. An overlay is a copy of bridge main from when the branch was first indexed, so one forked before main had the repo's uses lists them only in files the branch has re-indexed since. Against a deployment older than this release, which refuses the argument, the language server reads the references again without it.
