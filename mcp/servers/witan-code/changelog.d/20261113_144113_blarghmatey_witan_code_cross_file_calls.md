### Added

- The indexer resolves calls into other files of the repo through each file's imports, for Python (absolute and relative imports, `from pkg import mod`, `import pkg.mod as m`) and TS/JS (relative `import { f }` and `import * as ns`). A call whose callee is an imported name or an attribute chain rooted at one (`f()`, `mod.f()`, `Cls.method()`) gets a `Calls`/`References` edge to the symbol in the other file, so `code_callers`, `code_impact` and `witan code diff-impact` now list callers in other modules, on main and branch views alike. Each import of a repo file also gets an `Imports` edge to that file's `<module>` symbol. Calls through an instance (`obj.method()`), re-exports, star imports, `require()` and path aliases are not followed. Existing stores need one `witan-code reindex` (or a forced CI index) to get these edges for files that have not changed since.
- Re-indexing a file re-links the stored files that import it, since deleting its symbols also deletes every edge into them. The edit hook's one-file run therefore keeps a module's cross-file callers, and a function added to a module after its caller was written is linked when the module is indexed. This reads the new `importer_files` query; against a deployment older than this client the read is refused, logged as `witan.code.index.relink_skipped`, and the run continues without re-linking.

### Changed

- `witan code diff-impact` takes "tests to run" from a symbol's callers when the graph can reach them (a Python or TS/JS function or class). The `git grep` name search now runs only for methods, for languages without import resolution, and for a repo with no code graph, and the label drops "(stand-in)".
