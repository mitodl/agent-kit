### Added

- The indexer records each use of a name imported from a shared package namespace (today `mitol.*`, the namespaces package consumers are extracted for) whose module is not a file of the repo, as `ExternalUse` rows in the bridge: every load of the name (a call, a base class, a constant), with its line and enclosing symbol. A reindex replaces a re-parsed file's uses, and a full-repo index drops the uses of a file that left the repo.
- `code_find_references` on a definition in a shared package namespace also returns its uses in other indexed repos (at most 200), matched by its module path and by the parent package that re-exports it (`mitol.common.utils.now_in_utc` as well as `mitol.common.utils.datetime.now_in_utc`). A package's name for a definition counts only when the package's `__init__` re-exports it from that submodule. The language server's references therefore cross repos, and hovering a definition's own line names its uses in repos no workspace folder has open. This replaces the 0.34.0 limit of references to the definition's own repo. When the bridge cannot answer the uses read (a bridge or deployment from before `ExternalUse`), references log a warning and return the definition repo's own rows.
- The indexer writes an `Imports` edge from a Python package's `__init__` to each definition it re-exports from one of its own submodules: `from .sub import name` or `from pkg.sub import name` (an `as` alias to another name is not followed, since the edge cannot carry it), or `from .sub import *`, which takes the submodule's literal `__all__` when it declares one and its public top-level definitions otherwise. `importing_files` in `code_read.gq` reads them. Before this, `Imports` edges only linked a file to its own definitions.

### Changed

- `INDEX_VERSION` is 3, so each repo's next index of its default branch re-parses every file and writes its uses and re-exports. The `code-bridge` graph has to carry the `ExternalUse` schema (0.35.0) before this release indexes into it, because a load carrying a type the graph lacks fails the whole bridge write. A branch index through a deployed witan older than this release still writes its bindings and uses, but deletes uses in every re-parsed file rather than only where some are stored, and a full-repo index leaves the uses of a file that left the repo carrying no package binding, because that server lacks the new `external_use_files` query.
